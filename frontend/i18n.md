## Architecture

Public routes live in `src/app/[locale]`; private routes have a separate English root in `src/app/(private)`. `src/proxy.ts` handles locale URLs and redirects. Shared routing/request/navigation/publication configuration lives in `src/i18n`; UI message trees in `src/messages`. Keep feature narrative translations in each feature's `data/locales/{es,fr}.json`, keyed by stable record IDs. Do not ship all catalog translations through the client provider.

Use the supported `setRequestLocale` path for Next.js 16.2.6. Do not enable experimental root-params or upgrade Next just for this implementation. Separate roots use Next's global-not-found support.

Missing messages fall back to English at runtime. Missing entity translations fall back as a whole entity. Audits fail on missing keys, incomplete record fields/arrays, unexpected records, or absent locales. Draft status never means human-reviewed.

Public filters and relationships use canonical IDs/source values, not translated names. Images, URLs, prices, ratings, feature flags, and source identifiers are not translated. Localized narrative fields and live operational values have separate ownership. Numeric live prices and featured flags override display defaults without replacing translated descriptions. Public API reads use the configured `API_BASE_URL` server-side and the existing same-origin rewrite in browsers. Operational catalogue pages revalidate after one hour. Forms retain existing backend schemas and operator-readable canonical context; free text is never translated automatically.

## Editing translations

- Public pages compose feature sections directly. There are no screen wrappers.
- Shared UI uses `useCopy()` in synchronous components and `await getCopy()` in async server pages **after** `setRequestLocale(locale)`. The English phrase stays next to the markup; its stable key lives in `src/messages/{en,es,fr}.json` under `Copy`. `Common` holds document-level copy. Generate a new phrase key with `node scripts/i18n-key.mjs "English UI phrase"`, add that key to all three message files, and run the audit. Existing source wording changes need a new key. Runtime English fallback is for resilience; missing registered messages fail the audit.
- Narratives live in `src/features/<feature>/data/locales/es.json` and `fr.json`, keyed by canonical slug or stable gallery/review ID. `data/localized.ts` is server-only. English records remain in the original data files. Keep every field and array item when editing an entity; an incomplete entity falls back to its complete English source.
- Pass localized data to client grids, navigation and review components. Do not import server-only catalogue loaders into client components. Stable enquiry styles have their own small data file.
- Preserve source slugs, image paths, counts, numeric prices and ratings. Tour style keys, destination relationship names and article category keys stay canonical. Translation changes display labels only. Enquiries send canonical tour/destination names and style values; visitor free text remains untouched.

## Draft provenance and publication

Spanish and French copy was machine drafted on 2026-10-21 using Google Translate, with ICU placeholders and company/platform names protected, then checked for structural completeness. A few short UI labels were edited directly. Automated checks do not establish fluency or factual accuracy; a fluent reviewer/client must approve travel terminology, claims, tone and proper names. All English source content remains available for comparison.

After approval, change the relevant value in `src/i18n/publication.ts` from `draft` to `published`, update the publication assertions in the regression tests, rebuild, and repeat the audit and route checks. Canonicals, robots, hreflang, Open Graph alternatives and sitemap all derive from this setting. Draft pages stay crawlable so search engines can read their `noindex`; hiding them with robots.txt would prevent that. Changing publication status does not translate or review content automatically.

## Local production checks

```bash
corepack pnpm typecheck
corepack pnpm test
corepack pnpm i18n:audit
corepack pnpm build
corepack pnpm start --port 3104
# In a second terminal; override I18N_BASE_URL when needed:
corepack pnpm i18n:routes
corepack pnpm i18n:browser
```

The browser check requires Google Chrome at `/usr/bin/google-chrome`; it uses Chrome DevTools, writes screenshots to `/tmp`, and mocks all form submissions so it does not contact clients or subscribe test addresses. The route check covers all 399 localized public pages, redirects, unknown routes, login and search discovery. Authenticated admin workflows need a test backend and credentials and are outside this public-site change.
